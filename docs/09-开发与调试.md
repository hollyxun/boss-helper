# 09 · 开发与调试

## 1. 环境准备

| 工具                    | 说明                                           |
| ----------------------- | ---------------------------------------------- |
| **Node.js**             | 建议 20+；CI 使用 Node.js 22                   |
| **npm**                 | Node.js 包管理器，仓库使用 `package-lock.json` |
| Git                     | 版本控制                                       |
| Chrome / Edge / Firefox | 加载未打包扩展                                 |

```bash
git clone https://github.com/hollyxun/boss-helper.git
cd boss-helper
npm install
```

`npm install` 会触发 `postinstall: node scripts/wxt-run.mjs prepare`，生成 `.wxt/` 目录和类型声明。没有这一步，`tsconfig.json` 的 `extends: "./.wxt/tsconfig.json"` 会失败。

> `scripts/wxt-run.mjs` 直接调用 WXT 的 `prepare` / `build` / `zip` 公共 API，并在命令完成后 `process.exit(0)`。原因是 WXT 0.21.5 在 Windows 上执行非 dev 命令后会残留 MessagePort/worker 句柄，CLI 进程无法自然退出。

> 仓库根目录的 `.npmrc` 设置了 `legacy-peer-deps=true`：`openapi-typescript@7` 的 peer 仍要求 TypeScript 5，而项目使用 TypeScript 6（`vue-tsc` 目前无法驱动 TypeScript 7 的原生包结构）。`zod` 与 `vite` 已显式加入依赖，避免 legacy 模式漏装 AI SDK 等 peer。

## 3. 加载扩展

`wxt.config.ts` 中：

```ts
webExt: {
  disabled: true
}
```

这表示 `npm run dev` **不会自动拉起浏览器**，需要手动加载产物目录。

### 3.1 Chrome / Edge

1. 打开 `chrome://extensions`（Edge 为 `edge://extensions`）
2. 打开右上角“开发者模式”
3. 点击“加载已解压的扩展程序”
4. 选择 `.output/` 下 WXT 终端提示的目录

构建产物目录由 `outDirTemplate` 决定：

```ts
outDirTemplate: '{{browser}}-mv{{manifestVersion}}'
```

因此生产构建通常是 `.output/chrome-mv3`、`.output/firefox-mv3`、`.output/edge-mv3`。开发模式的目录名以 `npm run dev` 终端输出为准。

### 3.2 Firefox

1. 打开 `about:debugging#/runtime/this-firefox`
2. 点击“临时载入附加组件”
3. 选择产物目录中的 `manifest.json`

Firefox 要求 `strict_min_version: '109.0'`，并且构建脚本使用 `--mv3`。

### 3.3 修改后如何生效

- **content script / background / manifest**：通常需要重新加载扩展
- **页面主世界脚本 `boss.js`**：需要刷新 Boss 页面
- **Vue 组件**：开发模式下有 HMR，但 Shadow DOM 内的 UI 不保证热更新；刷新页面最稳
- **`wxt.config.ts` / manifest / 权限**：必须重新构建并重新加载扩展

## 4. 类型检查、Lint 与格式化

### 4.1 `npm run check`

- 使用 `vue-tsc --noEmit`
- 依赖 `.wxt/tsconfig.json`
- 会覆盖 `.ts`、`.vue`、`.tsx`
- 当前项目没有独立的 `test` 脚本，也没有测试框架

> 当前 `npm run check` 仍会报告源码中已有的严格类型错误（迁移前同样存在）。本次 Node.js 迁移只保证 `npm install`、`npm run build`、`npm run zip` 可用，CI 暂未执行 `check`。

### 4.2 `npm run lint`

`oxlint.config.ts`：

```ts
plugins: ['import', 'vue', 'jsx-a11y', 'oxc', 'typescript']
rules: {
  'eslint/no-unused-expressions': ['error', { allowShortCircuit: true }],
  'typescript/consistent-type-imports': 'error',
  'import/consistent-type-specifier-style': 'error',
  'typescript/no-redundant-type-constituents': 'off',
}
ignorePatterns: ['*.min.js', '/packages', '/.claude']
options: { typeAware: true }
```

### 4.3 `npm run fmt`

`oxfmt.config.ts`：

```ts
{
  semi: false,
  singleQuote: true,
  sortImports: { partitionByComment: true },
  ignorePatterns: ['*.min.js', '/packages', '/.claude'],
}
```

不要对 `packages/`、`.claude/`、`*.min.js` 做格式化。

## 5. 调试日志

日志只有一套实现：`src/utils/logger.ts` 是封装，写进 `src/composables/useLogs.ts` 的存储，由面板「日志」页展示。**不写 console**，也没有悬浮调试面板——`devlog-ui` 及其 `sessionStorage` 崩溃恢复、`Ctrl+Shift+L` 面板都已移除，`logger.configure` 不再存在。

### 5.1 设置日志级别

`src/utils/logger.ts` 在模块加载时读一次级别，低于它的调用直接丢弃：

```ts
const minLevel = localStorage.getItem('__BH_LOG_LEVEL__') ?? 'debug'
```

在 Boss 页面控制台执行（改完要刷新页面才生效）：

```js
localStorage.setItem('__BH_LOG_LEVEL__', 'warn')
location.reload()
```

可选级别：`debug`、`info`、`warn`、`error`；默认 `debug`（全写）。日志量大时把它调到 `warn`，只保留警告与报错。

### 5.2 日志页里的调试记录

- 三类来源：`job`（投递结果）、`ai`（AI 调用）、`system`（系统消息 + 调试日志）
- `logger` 写出来的都归 `system`，标签为 `调试` / `信息` / `警告` / `错误`
- 级别 → 状态：`debug`/`info` 走灰色 `info`；`warn` 走橙色 `skip`（不进「异常」，避免「投递过滤」这类正常分支把异常页刷满）；`error` 走红色 `error`
- 「详情」里展开**上下文 / 参数**，超过 1200 字截断
- 同名的 `debug` 日志按「文案 + `id`/`task_id`/`job_key` 作用域」合并成一条，行尾显示 `×N`，防止 AI 流式分片之类的刷屏挤掉投递记录
- 筛选：全部 / AI 调用 / 投递 / 系统 / 异常；关键词搜索会命中参数内容
- 内存保留 400 条，最近 200 条写入 `localStorage`（`boss-helper:logs`），刷新后仍在
- AI 调用记录含**完整提示词与模型回复**，可以直接用来排查「为什么这次没通过」

### 5.3 日志上下文与 span

业务代码使用：

```ts
const log = logger.withContext({ id: 'workflow-execute', job_key, job_name })
log.info('...')
log.error('...', e)

const span = logger.span('LLMTest')
span.info('...') // 过程日志先在内存里攒着
span.end() // 结束时合并成一条「流程结束：LLMTest」，带耗时与全部过程日志
```

常见 `id`：

- `workflow-rebuild`
- `workflow-execute`
- `workflow-end`

## 6. 调试不同执行环境

DevTools 的 Console 默认只显示页面主世界。需要切换上下文：

| 环境                 | 在 DevTools 中怎么看                                         |
| -------------------- | ------------------------------------------------------------ |
| 页面主世界 `boss.js` | Console 默认上下文；Sources 中可看到注入的脚本               |
| content script       | Console 顶部上下文下拉选择扩展的 isolated world              |
| background           | `chrome://extensions` → 该扩展 → “Service Worker”/“检查视图” |
| Shadow DOM UI        | Elements 中 `boss-helper-job` → `#shadow-root (open)`        |

快速定位 Shadow DOM：

```js
// 首次注入是 boss-helper-job；扩展重载后又注入过一次会是 boss-helper-job-2 …
// 用属性定位更稳：
document.querySelector('[data-boss-helper-host]')?.shadowRoot
```

查看扩展存储：

```js
// 在扩展的 background 或 content 上下文
chrome.storage.local.get(console.log)
chrome.storage.sync.get(console.log)
```

查看图片库：

- DevTools → Application → IndexedDB → `ExtensionGlobalDB` → `images`

## 7. 常见问题排查

| 现象                                   | 可能原因                                                                                                          | 排查/处理                                                                                                                                                                                                                  |
| -------------------------------------- | ----------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 页面没有出现面板                       | 不在 `zhipin.com`；扩展未加载；页面结构变化                                                                       | 控制台执行 `document.querySelector('[data-boss-helper-host]')` / `document.querySelector('boss-helper-job')` 看宿主是否注入；确认扩展已启用；刷新页面（日志不写 Console，Vue 桥已移除，没有「未找到 vue 根组件」这类提示） |
| 提示“未获取到用户ID”                   | `window._PAGE.encryptUserId` 为空                                                                                 | 确认已登录；刷新；可能是页面版本变化                                                                                                                                                                                       |
| 日志里 `code=37`                       | 安全网关没接受校验令牌，也可能只是这一段被限速；**不是未登录**；连点同条件搜索、或页面 `__zp_stoken__` 没重新签发 | 前两次只让当前岗位失败，连续 3 次才停整轮（`useRiskControl` 的阈值）；刷新 Boss 页面让站点重签令牌，再隔几分钟；停止连点；面板搜索有结果或命中风控时同条件拦 60s、其余只拦最小 8s，翻页失败按 8s→20s 退避并会自行停止      |
| 日志里 `code=36`                       | 账号级风控，已经要人工过一次验证                                                                                  | 到 Boss 页面自己点一下、把验证/滑块做完再投；这类不该由扩展绕，继续请求只会加重                                                                                                                                            |
| “未获取到 Boss 登录凭证（bst）”        | `bst` Cookie 取不到，请求已在本地被拦下                                                                           | 确认已登录并刷新页面；不再发无凭证请求，避免误判成风控                                                                                                                                                                     |
| 点击「开始工作」是灰的 / 没反应        | 岗位列表为空（还没搜过、搜索被节流、或 Boss 返回 0 条）；配置把岗位全滤掉了；`workflow` 未构建                    | 先在「筛选」页搜一发；看列表上方「共 N 个 · 配置过滤掉 M 个」；关掉「按配置过滤」或放宽筛选配置；再看日志                                                                                                                  |
| 下拉到底没有新职位                     | 翻页冷却中；`searchMeta.hasMore` 已被置 `false`（连续三次翻页失败或命中风控）；Boss 没有更多了                    | 等冷却结束再拉；换条件重搜或刷新页面；命中风控时先按提示完成验证                                                                                                                                                           |
| 投递到 120 次后失败                    | Boss 软限制弹窗                                                                                                   | 代码会自动确认并重试；仍失败则等待次日                                                                                                                                                                                     |
| 投递到 150 次后失败                    | 硬限制                                                                                                            | `LimitError`，无法绕过                                                                                                                                                                                                     |
| “操作频繁”                             | 风控                                                                                                              | 增大延迟，停止一段时间                                                                                                                                                                                                     |
| AI 请求 CORS                           | 第三方 API 不允许浏览器跨域                                                                                       | 换支持 CORS 的中转/服务                                                                                                                                                                                                    |
| AI 请求 401/404                        | Key、Base URL、模型名错误                                                                                         | 用“模型测试”逐个验证                                                                                                                                                                                                       |
| AI 一直不返回                          | 超时单位被误解                                                                                                    | `other.timeout` 是毫秒，默认 18000=18 秒                                                                                                                                                                                   |
| AI 筛选全被过滤                        | 模型输出没通过 zod 顶层校验，被判成「无结论」拦下                                                                 | 看日志里的「格式问题：…」，它会指明是哪个字段不对（如 `match.salary 应为 object，实际 缺失`、`match.skill 的 level 不在约定值里：ok`）；据此改提示词的输出格式段                                                           |
| 招呼语没发出去                         | MQTT 未连接、token/wt 失效、Boss 数据异常                                                                         | 看面板「日志」页里的 `消息发送ws`（由 `logger.error` 写入，不在 Console）；检查 `getBossData`                                                                                                                              |
| 图片招呼语失败                         | 图片 key 失效/未上传                                                                                              | 重新在高级招呼语中选图并保存                                                                                                                                                                                               |
| 高德报 `INVALID_USER_KEY`              | Key 错误或未开通 Web 服务                                                                                         | 在高德控制台创建“Web 服务”Key                                                                                                                                                                                              |
| 类型检查报 `.wxt/tsconfig.json` 不存在 | 没跑 `wxt prepare`                                                                                                | `npm install` 或 `node scripts/wxt-run.mjs prepare`                                                                                                                                                                        |
| `npm run check` 报类型错误             | 源码中已有的严格类型问题（迁移前也存在）                                                                          | 当前 CI 不强制执行；修复后再纳入 CI                                                                                                                                                                                        |
| 修改代码后页面没变化                   | 只刷新了页面，没重载扩展                                                                                          | 重新加载扩展 + 刷新页面                                                                                                                                                                                                    |

### 7.1 更细的排查顺序

**投递失败**

1. 看「日志」页对应条目的 `tag` / `title` / `message`
2. 看 `jobResultMaps` 对应卡片的状态与 `reason`
3. 看条目的 `reason` —— `bossApiError` 生成的错误文本自带 `code=<Boss 的 code>` 与 `｜zpData: <键名 + 截断摘要>`，先在日志里分辨 37（安全校验没被接受）和 36（账号风控），不用再去 Network 里翻；Network 过滤 `friend/add.json` 只是核对原文
4. 看 `statistics.todayData.success` 是否已达到 `deliveryLimit`
5. `PublishError` / `LimitError` / `RateLimitError` / `SecurityCheckError` / `AccountRiskError` 只在代码内部抛出、不会打到 Console；投递失败统一由 `logger.error('投递失败', res)` 呈现在「日志」页

**聊天失败**

1. 「日志」页看 `消息发送ws`（由 `logger.error` 写入，不在 Console）
2. Network 看 `get/wt` 是否返回 `code: 0`
3. WS 面板看 `wss://ws6.zhipin.com/chatws` 是否 101
4. 检查 `window._PAGE.token` 是否存在
5. 检查 `getBossData` 返回的 `data.bossId`、`securityId`

**配置不生效**

1. 确认点了“保存配置”
2. 确认对应配置项打了勾（`enable`）
3. 确认这一项在配置页有展示（地址配置 / 高德当前默认不展示，放回方式见 `05-配置系统.md` 1.4）
4. 停止后重新开始（工作流在开始时才重建）
5. 看 `local:web-geek-job-FormData` 是否正确写入

## 8. 扩展开发指南

### 8.1 新增一个筛选任务

完整步骤见 [04-投递工作流.md](./04-投递工作流.md#8-如何新增一个过滤任务)。简要版：

1. `types/formData.ts` 加字段
2. `conf/info.ts` 加默认值与帮助文案
3. `useApplying/handles.ts` 加 `defineTaskHandler`
4. `entrypoints/boss/delivery.ts` 注册
5. `entrypoints/boss/index.ts` 的 `getConfigItems()` 加 UI
6. 跑 `npm run check` 与 `npm run lint`

### 8.2 新增一个站点适配

理论上：

1. 新建 `src/entrypoints/<site>/index.ts`
2. 继承 `HelperContext<C, T, S>`
3. 实现 `onMount`、`getActiveJobs`、`loadMoreActiveJobs`、`start`、`sendMessage`、`uid`、`userInfo`、`key`、`label`、`getConfigItems`（可选覆盖 `onPanelOpen`）
4. 新建 `delivery.ts` 定义任务
5. 在 `content.ts` 中按域名注入
6. 注册自定义元素（可直接复用 `src/index.ts` 的 `run`）

实际成本：

- `App.vue` 中有 Boss 专属假设（面板入口、状态文案）
- `message` 层与 UI 层耦合较紧
- 建议先抽象出站点无关的 `HelperContext` 接口，再考虑第二站点

### 8.3 新增 AI Provider

见 [06-AI能力.md](./06-AI能力.md#23-新增-provider-的成本)。

### 8.4 新增存储键

- 需要跨设备同步：不加前缀（默认 `sync:`）
- 需要大容量/本地：显式 `local:`
- 临时会话：`session:`
- 企业策略：`managed:`

注意 `browser.storage.sync` 有配额限制（约 100KB/项、8KB/项更严格的旧限制），不要把大对象放 sync。

## 9. 手工测试清单

项目没有自动化测试，建议每次改动至少验证：

- [ ] 页面加载后 `boss-helper-job` 出现，UI 样式正常
- [ ] 打开面板按上次条件自动搜出发，卡片数量与面板搜索结果一致（岗位列表只来自面板搜索，刻意不与页面岗位同步）
- [ ] 点“开始”能逐条处理，卡片状态会变化
- [ ] 暂停/继续/重置行为正确
- [ ] 每个启用的过滤器至少命中一次（用构造数据或真实岗位）
- [ ] 达到 `deliveryLimit` 会停止
- [ ] 翻页失败会停止并提示
- [ ] 统计数字与日志一致
- [ ] 保存/重载/预设/导入导出正常
- [ ] AI 模型测试、AI 筛选、AI 招呼语正常（如启用）
- [ ] 自定义招呼语文本/图片正常
- [ ] Chrome / Edge / Firefox 至少各构建一次

## 10. 贡献注意事项

根目录 `CONTRIBUTING.md` 的核心要求：

- 小而专注，一个 PR 解决一个问题
- 改动规模与问题规模匹配
- 新功能/大改先开 Issue 讨论
- 不要顺手重构无关代码
- 保持代码简单，优先修复真实问题

提交前建议：

```bash
npm run fmt
npm run lint
npm run check
npm run build
```

不要把以下内容提交到仓库：

- 真实的 `api_key`
- 测试账号 Cookie / token
- `node_modules`、`.output`、`.wxt`
- 个人抓包数据中的手机号、身份信息

下一篇：[10-构建发布与兼容性.md](./10-构建发布与兼容性.md)。
