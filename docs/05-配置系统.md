# 05 · 配置系统

boss-helper-plus 的配置分为三块：

1. **投递配置** `FormData`：筛选、招呼语、延迟、统计上限等，配置页 / 简历页改动后**自动保存**（防抖 800ms，静默）
2. **AI 模型配置** `ModelConf[]`：手动保存，见 [06-AI能力.md](./06-AI能力.md)
3. **其它本地状态**：统计、去重集合、缓存、公告已读

本文主要讲投递配置，以及配置的存储、迁移、预设和常见坑。

涉及文件：

- `src/types/formData.ts`：`FormData` 类型
- `src/composables/conf/info.ts`：`defaultFormData`、`formInfoData`
- `src/composables/conf/index.ts`：加载、保存、迁移、预设、导入导出
- `src/components/Tabs/Config.vue` 与 `ConfigItem/*`：配置 UI
- `src/message/contentScript.ts`：存储键前缀规则

## 1. `FormData` 结构与默认值

`FormData` 是一个很大的扁平对象，字段大致分为六类。

### 1.1 筛选类

| 字段                | 类型                             | 默认值                                                                                                    | 作用            |
| ------------------- | -------------------------------- | --------------------------------------------------------------------------------------------------------- | --------------- |
| `company`           | `FormDataSelect`                 | `{ include:false, value:[], options:[], enable:false }`                                                   | 公司名包含/排除 |
| `jobTitle`          | `FormDataSelect`                 | `{ include:true, value:[], options:[], enable:false }`                                                    | 岗位名包含/排除 |
| `jobContent`        | `FormDataSelect`                 | `{ include:false, value:[], options:[], enable:false }`                                                   | 工作内容关键词  |
| `hrPosition`        | `FormDataSelect`                 | `{ include:true, value:[], options:['经理','主管','法人','人力资源主管','hr','招聘专员'], enable:false }` | HR 职位精确匹配 |
| `jobAddress`        | `FormDataSelect`                 | `{ value:[], options:[], enable:false, include:true }`                                                    | 工作地址包含    |
| `salaryRange`       | `FormSalaryRangeInput`           | 见下                                                                                                      | 薪资范围        |
| `companySizeRange`  | `FormDataRangeInput`             | `{ value:[500,2000,true], enable:false }`                                                                 | 公司规模        |
| `activityFilter`    | `FormDataCheckbox`               | `true`                                                                                                    | 过滤不活跃      |
| `friendStatus`      | `FormDataCheckbox`               | `true`                                                                                                    | 过滤已好友      |
| `bossGoldMedalHr`   | `FormDataCheckbox`               | `false`                                                                                                   | 过滤金牌面试官  |
| `goldHunterFilter`  | `FormDataCheckbox`               | `false`                                                                                                   | 过滤猎头        |
| `sameCompanyFilter` | `FormDataCheckbox & { expire? }` | `{ value:false, expire:0 }`                                                                               | 相同公司去重    |
| `sameHrFilter`      | `FormDataCheckbox & { expire? }` | `{ value:true, expire:0 }`                                                                                | 相同 HR 去重    |

`FormDataSelect`：

```ts
{
  include: boolean // true=包含/白名单，false=排除/黑名单
  value: string[]  // 关键词
  options: string[]// 可选/历史选项
  enable: boolean  // 是否启用
}
```

`salaryRange`：

```ts
{
  value: [8, 13, false],          // K，第三位 false=宽松
  advancedValue: {
    H: [0, 1, false],             // 元/时
    D: [0, 1, false],             // 元/天
    M: [0, 1, false],             // 元/月
  },
  enable: false,
}
```

`FormDataRange = [min, max, strict]`：

- `strict = true`：严格，职位区间必须完全落在目标区间内
- `strict = false`：宽松，区间有重叠即可

### 1.2 招呼语类

| 字段                     | 默认值                                                             | 说明                                 |
| ------------------------ | ------------------------------------------------------------------ | ------------------------------------ |
| `customGreeting.value`   | `''`                                                               | 字符串或 `CustomGreetingItem[]`      |
| `customGreeting.enable`  | `false`                                                            | 是否发送自定义招呼语                 |
| `greetingVariable.value` | `false`                                                            | 是否渲染 `{{ }}` 变量                |
| `aiGreeting`             | `{ enable:false, prompt:[...] }`                                   | AI 招呼语                            |
| `aiFiltering`            | `{ enable:false, prompt:[...], skipReject:true, skipWatch:false }` | AI 筛选（投递前执行）                |
| `aiReply`                | `{ enable:false, prompt:[...] }`                                   | AI 自动回复（0.0.2 起可用）          |
| `resume.summary`         | `''`                                                               | AI 生成的候选人摘要，供过滤/回复使用 |

`CustomGreetingItem`：

```ts
type CustomGreetingItem =
  { type: 'text'; content: string } | { type: 'image'; image: string; model?: File }
```

- `image` 存的是 IndexedDB 的 key（`img-<md5>`），不是 URL
- 编辑时会把图片从 IndexedDB 取回为 `File`，保存时重新算 MD5 并存回

### 1.3 投递控制类

| 字段                    | 默认值 | 说明                                                         |
| ----------------------- | ------ | ------------------------------------------------------------ |
| `deliveryLimit.value`   | `120`  | 今日投递上限，UI 范围 1~155                                  |
| `delayDeliveryStarts`   | `3`    | 点击开始后等待秒数                                           |
| `delayDeliveryInterval` | `5`    | 每个职位之间等待秒数                                         |
| `delayDeliveryPageNext` | `60`   | 翻页前等待秒数；投递期间唯一的翻页限速（下拉加载此时不生效） |
| `delayMessageSending`   | `2`    | 发送招呼语前的可编辑等待时间                                 |

### 1.4 高德地图

```ts
amap: {
  key: '',
  origins: '',            // 起点经纬度 "lng,lat"
  straightDistance: 0,    // km，0=禁用
  drivingDistance: 0,
  drivingDuration: 0,     // 分钟，0=禁用
  walkingDistance: 0,
  walkingDuration: 0,
  enable: false,
}
```

**这一组默认不在配置页展示。** 「地址配置」已从 `BossHelperCtx.getConfigItems()` 的分组列表里移除，面板上看不到、也改不了；但 `amap` 字段、`tasks.amap()` 任务、`Address.vue` 组件、`utils/amap.ts` 全部保留。

不启动的原因是任务工厂函数第一步就读 `amap.enable`：

```ts
// handles.ts → amap 任务
if (!ctx.helper.conf.formData.amap.enable) return
```

`enable` 默认 `false` → 工厂返回 `undefined` → 该任务不进管线 → 不会调高德接口，也不会因为「高德地图未初始化」误跳过岗位。

需要重新开放时，在 `getConfigItems()` 里「招呼语配置」和「延迟配置」之间放回这一组即可：

```ts
{
  label: '地址配置',
  value: 'address',
  items: [{ type: 'address', key: 'address' }],
},
```

| `useCache.value`     | `false` | 缓存开关：命中缓存的岗位直接跳过（普通 3 天 / AI 7 天 / 高德 5 天） |

### 1.6 版本

| 字段      | 默认值       | 说明                   |

## 2. 配置项展示规则

**没有分级。** 所有配置项一律常显，只按类别分进手风琴分组；不再有「新手 / 初学者 / 中级 / 高级」，`useConf()` 也不再返回 `configLevel`。

| 位置     | 分组       | 包含                                                                                                               |
| -------- | ---------- | ------------------------------------------------------------------------------------------------------------------ |
| 顶部卡片 | 运行设置   | 发送通知、启用缓存 + 清空缓存、投递数量                                                                            |
| 手风琴   | 筛选配置   | 公司名、岗位名、工作内容、HR 职位、工作地址；薪资范围、公司规模；活跃度、猎头、好友、金牌面试官、相同公司、相同 HR |
| 手风琴   | 招呼语配置 | 「禁用 Boss 自带招呼语」入口、自定义招呼语（含招呼语变量）                                                         |
| 手风琴   | 延迟配置   | 投递开始 / 投递间隔 / 投递翻页 / 消息发送（单位都是秒）                                                            |
| 手风琴   | 地址配置   | **不展示**，见 1.4 节                                                                                              |
| 底部     | —          | 保存 / 重载 / 推荐配置 / 导出 / 导入 / 清空、预设                                                                  |

「常显」不等于「生效」：每一项都自带 `enable` 复选框（或自己的 `value`），默认关闭，用户勾了才进管线。

### 2.1 面板列表的过滤开关

岗位列表右上角的「按配置过滤」开关（`jobListFilterEnabled`）既决定面板显示哪些岗位，也决定投递从哪些岗位出发——投递列表就是 `applyJobListFilter(getActiveJobs(), formData)`，和面板同一份实现（`useJobListFilter.ts`）。关掉它等于把面板里的全部岗位都投。

> 面板这一层只用列表字段判定。需要岗位详情才能判的筛选（金牌面试官、高德距离、AI 过滤、工作内容关键词、相同公司 / 相同 HR 去重、已沟通）依然在投递管线里执行，所以「显示 N 个」不等于「投出去 N 个」。

### 2.2 配置项描述

`formInfoData` 为每个字段提供 `label` 和 `data-help`，后者会出现在：

- 表单标题的 `title`
- 帮助模式下鼠标悬停的高亮提示
- 部分 `data-help` 会直接作为 Tooltip 文本

修改配置 UI 时，记得同步补 `formInfoData`，否则会出现空标签或没有帮助。

## 3. 存储键与读写路径

### 3.1 键前缀规则

`ContentCounter.genKey()`：

```ts
const prefixes = ['local:', 'session:', 'sync:', 'managed:']
return prefixes.some((p) => key.startsWith(p)) ? key : `sync:${key}`
```

- 显式写 `local:` → `browser.storage.local`
- 显式写 `sync:` → `browser.storage.sync`
- 不写前缀 → **默认 `sync:`**

> `ExtStorage`（`src/message/index.ts`）曾作为 `useStorageAsync` 的适配器走同一套前缀规则；外观配置下线后源码里已无 `useStorageAsync` 调用，它只剩一个无人引用的定义。

### 3.2 键清单

| 键                                        | 区域         | 内容                                 | 写入方                           |
| ----------------------------------------- | ------------ | ------------------------------------ | -------------------------------- |
| `local:web-geek-job-FormData`             | local        | 默认预设的 `FormData`                | 防抖自动保存                     |
| `local:web-geek-job-FormData-<timestamp>` | local        | 其它预设的 `FormData`                | 创建预设/自动保存                |
| `local:FormDataPrese`                     | local        | 当前预设 id                          | 保存/切换/创建                   |
| `local:FormDataPreses`                    | local        | 预设列表 `{label,value}[]`           | 保存/创建                        |
| `sync:conf-model`                         | sync         | AI 模型数组                          | 手动保存                         |
| `local:web-geek-job-Today`                | local        | 今日统计                             | 200ms 节流自动写                 |
| `local:web-geek-job-Statistics`           | local        | 历史统计数组                         | `updateStatistics`               |
| `local:sameCompany`                       | local        | `{ [uid]: { [jobKey]: timestamp } }` | 投递后每 3 个/轮末               |
| `local:sameHr`                            | local        | 同上                                 | 同上                             |
| `local:pipeline-cache`                    | local        | 岗位处理结果缓存                     | 投递命中/写回；清空缓存的按钮    |
| `boss-helper:logs`                        | localStorage | 运行日志（最近 200 条）              | `useLogs` 防抖写                 |
| `boss-helper:last-resume`                 | localStorage | 最近一次简历抓取结果（24 小时）      | `useBossResume`                  |
| `boss-helper:search-conditions`           | localStorage | 面板搜索条件                         | 搜索/清空时                      |
| `boss-helper:last-search`                 | localStorage | 搜索节流：上次请求的时刻/条件/结果   | `apply()` 发请求前读、出结果后写 |
| `local:alert:<id>`                        | local        | 公告已关闭                           | `Alert.vue`                      |
| `local:netConf-<key>`                     | local        | 远程通知已读时间                     | `netConf.ts`                     |
| IndexedDB `ExtensionGlobalDB/images`      | IndexedDB    | 聊天图片 `File`                      | background `setImage`            |

> 注意：上面四个 `boss-helper:*` 键由 `window.localStorage` 直接读写（`useLogs`、`useBossResume`、`useBossSearch`、`usePanelSearch`），**不走 `counter.storageGet/Set`，也不适用 3.1 节的 `local:/sync:` 前缀规则**；表里只是把它们和扩展存储并排列出，别误解成扩展的 `local` 区。

> 注意：AI 模型配置（含 `api_key`）默认走 `sync:`，如果浏览器账号开启了同步，密钥可能随扩展数据同步到其它设备。对密钥敏感的用户应了解这一点。

### 3.3 读取流程 `confInit()`

```ts
isLoading.value = true
try {
  const preset = await counter.storageGet(formDataPresetKey, 'default')
  const presets = await counter.storageGet(formDataPresetsKey, [
    { label: '默认配置', value: 'default' },
  ])
  formDataPreset.value = preset
  formDataPresets.value = presets

  let from = await counter.storageGet(formDataKey(), {})
  from = (await formDataHandler(from)) ?? from // 迁移
  const data = deepmerge(defaultFormData, from)
  Object.assign(formData, data)
} catch (e) {
  toast.add({ title: `配置加载失败: ${String(e)}`, color: 'error' })
} finally {
  isLoading.value = false
}
```

`formDataKey()`：

```ts
formDataPreset.value !== 'default'
  ? `local:web-geek-job-FormData-${formDataPreset.value}`
  : `local:web-geek-job-FormData`
```

### 3.4 保存流程 `confSaving()`

```ts
await counter.storageSet(formDataKey(), jsonClone(formData))
await counter.storageSet(formDataPresetKey, jsonClone(formDataPreset.value))
await counter.storageSet(formDataPresetsKey, jsonClone(formDataPresets.value))
toast.add({ title: '保存成功', color: 'success' })
```

- 保存的是**当前预设**对应的键
- 只保存这三个键，不保存统计/模型/集合
- 不会自动触发 `workflow.rebuild()`；相关代码被注释
- `jsonClone` 用于去掉 Vue 响应式 Proxy，避免 `storage.setItem` 序列化问题

### 3.5 载入/重置/导入导出

| 操作         | 实现                                                                                                                                                   | 注意                                                                                             |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------ |
| 重载配置     | `confReload()`：从当前预设键读取，deepmerge 默认值，再 `deepmerge(formData, v, { clone:false })`                                                       | 会覆盖当前未保存修改                                                                             |
| 使用推荐配置 | `confRecommend()`：把 `deliveryLimit/activityFilter/friendStatus/sameCompanyFilter/sameHrFilter/goldHunterFilter/notification/useCache/delay` 恢复默认 | 会 `confSaving(true)` 自动保存（Toast「已自动保存」）；但对 `formData` 的改动是 no-op，见第 7 节 |
| 清空配置     | `confDelete()`：把 `defaultFormData` 合并回 `formData`                                                                                                 | 同上：会 `confSaving(true)` 自动保存；对 `formData` 的改动是 no-op，见第 7 节                    |
| 导出         | `confExport()`：读取**存储中的**当前预设，导出 JSON                                                                                                    | 未保存的修改不会导出                                                                             |
| 导入         | `confImport()`：选择 JSON → 迁移 → `deepmerge(formData, json, { clone:false })` → `confSaving(true)`                                                   | 合并而非替换；导入后自动保存（Toast「导入成功，已自动保存」）                                    |

导出文件名固定为 `打招呼配置.json`（`confExport` 中写死），AI 模型导出为 `Ai模型配置.json`。

## 4. 配置迁移

`FROM_VERSION` 是一个 `[版本, 迁移函数][]` 数组：

```ts
const FROM_VERSION = [
  [
    '20250826',
    (from) => {
      /* 薪资/规模从字符串转 [min,max,false] */
    },
  ],
  [
    '20260521',
    (from) => {
      /* AI prompt 字符串转数组；jobAddress.include=true */
    },
  ],
  [
    '20260718',
    (from) => {
      /* 把 delay: { deliveryStarts, ... } 拍平成 delayDeliveryStarts... */
    },
  ],
  [
    '20261029',
    (from) => {
      /* 只替换「没改过」的旧版 AI 过滤默认提示词（含「求职评委」且无 {{ resume }}），用户自定义不动 */
    },
  ],
  [
    '20261103',
    (from) => {
      /* AI 过滤评分制 -> 六维匹配度：
         按旧 score 推导 skipReject / skipWatch（<=0 不拦，>60 连谨慎投递一起拦），删掉 score；
         只有「没改过」的旧默认提示词才换成新默认（认 interface aiFilteringItem，以及含「求职评委」却无 {{ resume }} 的更早版本），用户自定义的不动 */
    },
  ],
  [
    '20261104',
    (from) => {
      /* 0.0.5 的默认提示词要求 match 六个维度全部给齐，实测会把只填了部分维度的可用判断整份作废；
         换成核心两维（skill / direction）必填版。因为只跑最新一条迁移，这条自带上一条的 score 推导
         和旧默认提示词识别（多认一个「match 的六个维度必须全部给齐」标记） */
    },
  ],
]
```

`formDataHandler`：

```ts
for (let i = FROM_VERSION.length - 1; i >= 0; i--) {
  const [version, fn] = FROM_VERSION[i]
  if ((from?.version ?? '20240401') >= version) {
    break
  }
  from = fn(from)
  from.version = version
}
```

行为：

- 从最新版本往前遍历
- 只要配置版本已经大于等于某个版本，就**立即 break**
- 否则执行该迁移并把 `version` 设为该版本
- 因此，一个非常老的配置只会执行**最新的一条**迁移，中间的迁移会被跳过（例如 2024 年的配置不会执行 20260521 的 AI prompt 迁移）

这不一定会导致崩溃，因为：

- `deepmerge(defaultFormData, from)` 会补齐缺失字段
- `ChatModel.chat` 对 `prompt` 为字符串的情况有兜底：

```ts
if (typeof model.prompt === 'string') {
  messages = [{ role: 'user', content: model.prompt }]
}
```

但如果后续迁移之间有依赖关系，这个“只执行最新一条”的策略会埋雷。

## 5. 预设（多配置切换）

预设是“废弃多账号后”的替代方案：不同 Boss 账号可以各自保存一套配置，手动切换。

### 5.1 数据结构

```ts
formDataPreset: Ref<string> // 当前预设 id，默认 'default'
formDataPresets: Ref<{ label; value }[]> // 列表，默认 [{label:'默认配置', value:'default'}]
```

### 5.2 创建 `createPreset(label)`

1. `value = Date.now().toString()`
2. push 到 `formDataPresets`
3. 切换 `formDataPreset` 到新值
4. 写入预设列表、当前预设
5. 把当前 `formData` 写到 `local:web-geek-job-FormData-<value>`
6. Toast

### 5.3 切换 `switchPreset(value)`

1. 设置 `formDataPreset`
2. 写入 `local:FormDataPrese`
3. 调用 `init()` 重新加载该预设的配置

切换是即时的，不会提示保存当前修改。切换前应先保存。

### 5.4 删除预设

当前**没有删除预设的 UI 或函数**。只能通过浏览器扩展存储手动清理。

## 6. 配置 UI 的渲染机制

### 6.1 `getConfigItems()` 返回什么

`BossHelperCtx.getConfigItems()` 返回：

```ts
ComputedRef<
  [
    AlertItem[], // 顶部公告
    (ConfigAccordionItem | false)[], // 手风琴分组
  ]
>
```

每个分组包含 `items`，每个 item 是 `ConfigItem` 联合类型：

```ts
type ConfigItem =
  | { type: 'select'; key: string }
  | { type: 'checkbox'; key: string }
  | { type: 'checkbox-expire'; key: string }
  | { type: 'salaryRange'; key: string }
  | { type: 'companySizeRange'; key: string }
  | { type: 'customGreeting'; key: string }
  | { type: 'address'; key: string }
  | { type: 'appearance'; key: string }
  | { type: 'inputNumber'; key: string; fieldProps?; inputNumberProps? }
  | { type: 'alert'; ...AlertProps }
  | { type: 'div'; items?: (ConfigItem | false)[]; class?: string }
```

`ConfigItem.vue` 按 `type` 分发到不同组件；数组里的 `false` 表示这一项不渲染（分组被整体摘掉时用 `| false` 兜住，见「地址配置」）。

### 6.2 为什么用这种“配置描述”而不是直接写模板

- 同一套 `getConfigItems()` 可以被不同站点复用
- 布局（grid/flex）可以数据化
- 但类型较松散，`key` 是字符串，写错不会在编译期报错

### 6.3 启用与包含/排除

`FormItem.vue` 把“启用复选框”和“包含/排除单选”放在 label 区域：

- 复选框绑定 `enable`
- 单选组（包含 / 排除）绑定 `include`（仅当 `include != null`），一眼能看出当前值
- 整行是一个带边框的卡片：`rounded-md border border-border p-3`

## 7. 已知配置问题

### 7.1 `confRecommend` 与 `confDelete` 对 `formData` 是 no-op

`deepmerge` 的默认行为是**克隆 target**：

```ts
const output = options.clone ? { ...target } : target
```

而这两个函数调 `deepmerge(formData, ...)` 时既没接收返回值、也没传 `{ clone: false }`：

```ts
function confRecommend() {
  deepmerge(formData, recommendedValues) // 返回值被丢弃，formData 内存没变
  logger.debug('formData推荐配置已应用')
  void confSaving(true) // 保存的是「没被改动过」的 formData
  toast.add({ title: '推荐配置已应用，已自动保存', color: 'success' })
}

function confDelete() {
  deepmerge(formData, defaultFormData) // 返回值被丢弃
  logger.debug('formData已清空')
  void confSaving(true)
  toast.add({ title: '配置已清空，已自动保存', color: 'success' })
}
```

两者现在都会调用 `confSaving(true)` 并弹「已自动保存」的 Toast——所以**不是「不保存」**。但因为 `deepmerge` 的返回值被丢弃、`formData` 内存并未真正被改回默认值，落盘保存的仍是当前那份未变的配置。对比 `confReload`/`confImport` 都显式传了 `{ clone: false }`，可以确认这里漏传 `{ clone: false }` 是遗漏，内存层面的重置并不生效。

### 7.2 推荐配置列表包含不存在的 `delay`

```ts
['deliveryLimit', ..., 'delay'].reduce(...)
```

`FormData` 中没有 `delay` 字段（迁移后已拍平成 `delayDeliveryStarts` 等），所以这一项没有意义。

### 7.3 运行中修改配置不会生效

配置控件在 `workflowRunning` 时被 `UForm :disabled` 禁用；即使绕过 UI 修改，工作流也只在 `executeAll()` 开始时 `rebuild()`。

### 7.4 未保存的修改可能丢失

- 切换预设、重载、导入都会覆盖当前 `formData`
- 关闭页面也会丢失未保存修改
- 导出读取的是存储而不是内存

### 7.5 `salaryRange` 高级单位默认值

`advancedValue.H/D/M` 默认 `[0,1,false]`，一旦启用薪资筛选，时薪/日薪/月薪职位会被这组默认值过滤。启用薪资筛选时务必检查高级配置。

### 7.6 配置版本迁移不累积

见第 4 节：从最新版本倒序、遇到已满足即 break，老配置可能跳过中间迁移。
