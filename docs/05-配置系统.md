# 05 · 配置系统

boss-helper-plus 的配置分为四块：

1. **投递配置** `FormData`：筛选、招呼语、延迟、统计上限等，手动保存
2. **外观配置** `appearanceConf`：自动保存
3. **AI 模型配置** `ModelConf[]`：手动保存，见 [06-AI能力.md](./06-AI能力.md)
4. **其它本地状态**：统计、去重集合、缓存、公告已读、协议同意标记

本文主要讲前两块，以及配置的存储、迁移、预设和常见坑。

涉及文件：

- `src/types/formData.ts`：`FormData` 类型
- `src/composables/conf/info.ts`：`defaultFormData`、`formInfoData`
- `src/composables/conf/index.ts`：加载、保存、迁移、预设、导入导出
- `src/components/Tabs/Config.vue` 与 `ConfigItem/*`：配置 UI
- `src/message/contentScript.ts`：存储键前缀规则

## 1. `FormData` 结构与默认值

`FormData` 是一个很大的扁平对象，字段大致分为六类。

### 1.1 筛选类

| 字段                | 类型                             | 默认值                                                                                                    | 作用            |
| ------------------- | -------------------------------- | --------------------------------------------------------------------------------------------------------- | --------------- |
| `company`           | `FormDataSelect`                 | `{ include:false, value:[], options:[], enable:false }`                                                   | 公司名包含/排除 |
| `jobTitle`          | `FormDataSelect`                 | `{ include:true, value:[], options:[], enable:false }`                                                    | 岗位名包含/排除 |
| `jobContent`        | `FormDataSelect`                 | `{ include:false, value:[], options:[], enable:false }`                                                   | 工作内容关键词  |
| `hrPosition`        | `FormDataSelect`                 | `{ include:true, value:[], options:['经理','主管','法人','人力资源主管','hr','招聘专员'], enable:false }` | HR 职位精确匹配 |
| `jobAddress`        | `FormDataSelect`                 | `{ value:[], options:[], enable:false, include:true }`                                                    | 工作地址包含    |
| `salaryRange`       | `FormSalaryRangeInput`           | 见下                                                                                                      | 薪资范围        |
| `companySizeRange`  | `FormDataRangeInput`             | `{ value:[500,2000,true], enable:false }`                                                                 | 公司规模        |
| `activityFilter`    | `FormDataCheckbox`               | `true`                                                                                                    | 过滤不活跃      |
| `friendStatus`      | `FormDataCheckbox`               | `true`                                                                                                    | 过滤已好友      |
| `bossGoldMedalHr`   | `FormDataCheckbox`               | `false`                                                                                                   | 过滤金牌面试官  |
| `goldHunterFilter`  | `FormDataCheckbox`               | `false`                                                                                                   | 过滤猎头        |
| `sameCompanyFilter` | `FormDataCheckbox & { expire? }` | `{ value:false, expire:0 }`                                                                               | 相同公司去重    |
| `sameHrFilter`      | `FormDataCheckbox & { expire? }` | `{ value:true, expire:0 }`                                                                                | 相同 HR 去重    |

`FormDataSelect`：

```ts
{
  include: boolean // true=包含/白名单，false=排除/黑名单
  value: string[]  // 关键词
  options: string[]// 可选/历史选项
  enable: boolean  // 是否启用
}
```

`salaryRange`：

```ts
{
  value: [8, 13, false],          // K，第三位 false=宽松
  advancedValue: {
    H: [0, 1, false],             // 元/时
    D: [0, 1, false],             // 元/天
    M: [0, 1, false],             // 元/月
  },
  enable: false,
}
```

`FormDataRange = [min, max, strict]`：

- `strict = true`：严格，职位区间必须完全落在目标区间内
- `strict = false`：宽松，区间有重叠即可

### 1.2 招呼语类

| 字段                     | 默认值                                     | 说明                                     |
| ------------------------ | ------------------------------------------ | ---------------------------------------- |
| `customGreeting.value`   | `''`                                       | 字符串或 `CustomGreetingItem[]`          |

- 编辑时会把图片从 IndexedDB 取回为 `File`，保存时重新算 MD5 并存回

## 2. 配置级别（渐进式披露）

`configLevel` 的四个值与顺序：

```ts
beginner = 1
intermediate = 2
advanced = 3
expert = 4
```

`useConf()` 返回的 `configLevel` 是响应式布尔集合：

```ts
{
  intermediate: order.intermediate <= 当前级别,
  advanced: order.advanced <= 当前级别,
  expert: order.expert <= 当前级别,

```

### 2.2 配置项描述

`formInfoData` 为每个字段提供 `label` 和 `data-help`，后者会出现在：

修改配置 UI 时，记得同步补 `formInfoData`，否则会出现空标签或没有帮助。

## 3. 存储键与读写路径

### 3.1 键前缀规则

`ContentCounter.genKey()`：

```ts
const prefixes = ['local:', 'session:', 'sync:', 'managed:']
return prefixes.some((p) => key.startsWith(p)) ? key : `sync:${key}`
```

- 显式写 `local:` → `browser.storage.local`
- 显式写 `sync:` → `browser.storage.sync`
- 不写前缀 → **默认 `sync:`**

`ExtStorage` 是 `useStorageAsync` 的适配器，它最终调用 `counter.storageGet/Set`，所以也遵守这个规则。

### 3.2 键清单

| 键                                        | 区域      | 内容                                 | 写入方                |
| ----------------------------------------- | --------- | ------------------------------------ | --------------------- |
| `local:web-geek-job-FormData`             | local     | 默认预设的 `FormData`                | 手动保存              |
| `local:web-geek-job-FormData-<timestamp>` | local     | 其它预设的 `FormData`                | 创建预设/保存         |
| `local:FormDataPrese`                     | local     | 当前预设 id                          | 保存/切换/创建        |
| `local:FormDataPreses`                    | local     | 预设列表 `{label,value}[]`           | 保存/创建             |
| `sync:appearance-conf`                    | sync      | 外观配置                             | 自动保存              |
| `sync:conf-model`                         | sync      | AI 模型数组                          | 手动保存              |
| `local:web-geek-job-Today`                | local     | 今日统计                             | 200ms 节流自动写      |
| `local:web-geek-job-Statistics`           | local     | 历史统计数组                         | `updateStatistics`    |
| `local:sameCompany`                       | local     | `{ [uid]: { [jobKey]: timestamp } }` | 投递后每 3 个/轮末    |
| `local:sameHr`                            | local     | 同上                                 | 同上                  |
| `local:pipeline-cache`                    | local     | 管道缓存                             | 缓存管理器（未接入）  |
| `local:alert:<id>`                        | local     | 公告已关闭                           | `Alert.vue`           |
| `local:netConf-<key>`                     | local     | 远程通知已读时间                     | `netConf.ts`          |
| `local:boss-protocol`                     | local     | 旧版协议同意版本（当前 UI 已移除）   | —                     |
| IndexedDB `ExtensionGlobalDB/images`      | IndexedDB | 聊天图片 `File`                      | background `setImage` |

> 注意：AI 模型配置（含 `api_key`）默认走 `sync:`，如果浏览器账号开启了同步，密钥可能随扩展数据同步到其它设备。对密钥敏感的用户应了解这一点。

### 3.3 读取流程 `confInit()`

```ts
isLoading.value = true
try {
  const preset = await counter.storageGet(formDataPresetKey, 'default')
  const presets = await counter.storageGet(formDataPresetsKey, [
    { label: '默认配置', value: 'default' },
  ])
  formDataPreset.value = preset
  formDataPresets.value = presets

  let from = await counter.storageGet(formDataKey(), {})
  from = (await formDataHandler(from)) ?? from // 迁移
  const data = deepmerge(defaultFormData, from)
  Object.assign(formData, data)
} catch (e) {
  toast.add({ title: `配置加载失败: ${String(e)}`, color: 'error' })
} finally {
  isLoading.value = false
}
```

`formDataKey()`：

```ts
formDataPreset.value !== 'default'
  ? `local:web-geek-job-FormData-${formDataPreset.value}`
  : `local:web-geek-job-FormData`
```

### 3.4 保存流程 `confSaving()`

```ts
await counter.storageSet(formDataKey(), jsonClone(formData))
await counter.storageSet(formDataPresetKey, jsonClone(formDataPreset.value))
await counter.storageSet(formDataPresetsKey, jsonClone(formDataPresets.value))
toast.add({ title: '保存成功', color: 'success' })
```

- 保存的是**当前预设**对应的键
- 只保存这三个键，不保存统计/模型/集合
- 不会自动触发 `workflow.rebuild()`；相关代码被注释
- `jsonClone` 用于去掉 Vue 响应式 Proxy，避免 `storage.setItem` 序列化问题

### 3.5 载入/重置/导入导出

| 操作         | 实现                                                                                                                                                   | 注意                                             |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------ |
| 重载配置     | `confReload()`：从当前预设键读取，deepmerge 默认值，再 `deepmerge(formData, v, { clone:false })`                                                       | 会覆盖当前未保存修改                             |
| 使用推荐配置 | `confRecommend()`：把 `deliveryLimit/activityFilter/friendStatus/sameCompanyFilter/sameHrFilter/goldHunterFilter/notification/useCache/delay` 恢复默认 | 不自动保存；且当前实现存在 no-op 问题，见第 8 节 |
| 清空配置     | `confDelete()`：把 `defaultFormData` 合并回 `formData`                                                                                                 | 不自动保存；当前实现存在 no-op 问题，见第 8 节   |
| 导出         | `confExport()`：读取**存储中的**当前预设，导出 JSON                                                                                                    | 未保存的修改不会导出                             |
| 导入         | `confImport()`：选择 JSON → 迁移 → `deepmerge(formData, json, { clone:false })`                                                                        | 合并而非替换；导入后需手动保存                   |

导出文件名固定为 `打招呼配置.json`（`confExport` 中写死），AI 模型导出为 `Ai模型配置.json`。

## 4. 配置迁移

`FROM_VERSION` 是一个 `[版本, 迁移函数][]` 数组：

```ts
const FROM_VERSION = [
  [
    '20250826',
    (from) => {
      /* 薪资/规模从字符串转 [min,max,false] */
    },
  ],
  [
    '20260521',
    (from) => {
      /* AI prompt 字符串转数组；jobAddress.include=true */
    },
  ],
  [
    '20260718',
    (from) => {
      /* 把 delay: { deliveryStarts, ... } 拍平成 delayDeliveryStarts... */
    },
  ],
]
```

`formDataHandler`：

```ts
for (let i = FROM_VERSION.length - 1; i >= 0; i--) {
  const [version, fn] = FROM_VERSION[i]
  if ((from?.version ?? '20240401') >= version) {
    break
  }
  from = fn(from)
  from.version = version
}
```

行为：

- 从最新版本往前遍历
- 只要配置版本已经大于等于某个版本，就**立即 break**
- 否则执行该迁移并把 `version` 设为该版本
- 因此，一个非常老的配置只会执行**最新的一条**迁移，中间的迁移会被跳过（例如 2024 年的配置不会执行 20260521 的 AI prompt 迁移）

这不一定会导致崩溃，因为：

- `deepmerge(defaultFormData, from)` 会补齐缺失字段
- `ChatModel.chat` 对 `prompt` 为字符串的情况有兜底：

```ts
if (typeof model.prompt === 'string') {
  messages = [{ role: 'user', content: model.prompt }]
}
```

但如果后续迁移之间有依赖关系，这个“只执行最新一条”的策略会埋雷。

## 5. 预设（多配置切换）

预设是“废弃多账号后”的替代方案：不同 Boss 账号可以各自保存一套配置，手动切换。

### 5.1 数据结构

```ts
formDataPreset: Ref<string> // 当前预设 id，默认 'default'
formDataPresets: Ref<{ label; value }[]> // 列表，默认 [{label:'默认配置', value:'default'}]
```

### 5.2 创建 `createPreset(label)`

1. `value = Date.now().toString()`
2. push 到 `formDataPresets`
3. 切换 `formDataPreset` 到新值
4. 写入预设列表、当前预设
5. 把当前 `formData` 写到 `local:web-geek-job-FormData-<value>`
6. Toast

### 5.3 切换 `switchPreset(value)`

1. 设置 `formDataPreset`
2. 写入 `local:FormDataPrese`
3. 调用 `init()` 重新加载该预设的配置

切换是即时的，不会提示保存当前修改。切换前应先保存。

### 5.4 删除预设

当前**没有删除预设的 UI 或函数**。只能通过浏览器扩展存储手动清理。

## 6. 配置 UI 的渲染机制

### 6.1 `getConfigItems()` 返回什么

`BossHelperCtx.getConfigItems()` 返回：

```ts
ComputedRef<
  [
    AlertItem[], // 顶部公告
    (ConfigAccordionItem | false)[], // 手风琴分组
  ]
>
```

每个分组包含 `items`，每个 item 是 `ConfigItem` 联合类型：

```ts
type ConfigItem =
  | { type: 'select'; key: string }
  | { type: 'checkbox'; key: string }
  | { type: 'checkbox-expire'; key: string }
  | { type: 'salaryRange'; key: string }
  | { type: 'companySizeRange'; key: string }
  | { type: 'customGreeting'; key: string }
  | { type: 'address'; key: string }
  | { type: 'appearance'; key: string }
  | { type: 'inputNumber'; key: string; fieldProps?; inputNumberProps? }
  | { type: 'alert'; ...AlertProps }
  | { type: 'div'; items?: (ConfigItem | false)[]; class?: string }
```

`ConfigItem.vue` 按 `type` 分发到不同组件；`false` 用于按级别隐藏。

### 6.2 为什么用这种“配置描述”而不是直接写模板

- 同一套 `getConfigItems()` 可以被不同站点复用
- 配置级别、布局（grid/flex）可以数据化
- 但类型较松散，`key` 是字符串，写错不会在编译期报错

### 6.3 启用与包含/排除

`FormItem.vue` 把“启用复选框”和“包含/排除按钮”放在 label 区域：

- 复选框绑定 `enable`
- 按钮绑定 `include`（仅当 `include != null`）
- 颜色：包含=primary，排除=warning

## 8. 已知配置问题

### 8.1 `confRecommend` 与 `confDelete` 可能是 no-op

`deepmerge` 的默认行为是**克隆 target**：

```ts
const output = options.clone ? { ...target } : target
```

而这两个函数都没有接收返回值，也没有传 `{ clone: false }`：

```ts
function confRecommend() {
  deepmerge(formData, recommendedValues) // 返回值被丢弃
  toast.add(...)
}

function confDelete() {
  deepmerge(formData, defaultFormData) // 返回值被丢弃
  toast.add(...)
}
```

按当前实现，它们只会弹 Toast，**不会真正修改 `formData`**。对比 `confReload`/`confImport` 都显式传了 `{ clone: false }`，可以确认这是遗漏。

### 8.2 推荐配置列表包含不存在的 `delay`

```ts
['deliveryLimit', ..., 'delay'].reduce(...)
```

`FormData` 中没有 `delay` 字段（迁移后已拍平成 `delayDeliveryStarts` 等），所以这一项没有意义。

### 8.3 运行中修改配置不会生效

配置控件在 `workflowRunning` 时被 `UForm :disabled` 禁用；即使绕过 UI 修改，工作流也只在 `executeAll()` 开始时 `rebuild()`。

### 8.4 未保存的修改可能丢失

- 切换预设、重载、导入都会覆盖当前 `formData`
- 关闭页面也会丢失未保存修改
- 导出读取的是存储而不是内存

### 8.5 `salaryRange` 高级单位默认值

`advancedValue.H/D/M` 默认 `[0,1,false]`，一旦启用薪资筛选，时薪/日薪/月薪职位会被这组默认值过滤。启用薪资筛选时务必检查高级配置。

### 8.6 关键词直接拼正则

`jobContent` 的正则没有对用户输入做转义。输入 `C++`、`(`、`[` 等会构造非法或意外正则，导致任务抛错、该职位被标记为错误。

### 8.7 配置版本迁移不累积

见第 4 节：从最新版本倒序、遇到已满足即 break，老配置可能跳过中间迁移。
