# 10 · 构建发布与兼容性

## 1. 构建体系

BossHelper 使用 **WXT** 作为扩展框架，Vite 作为底层打包器。

`wxt.config.ts` 的关键配置：

```ts
export default defineConfig({
  srcDir: 'src',
  outDirTemplate: '{{browser}}-mv{{manifestVersion}}',
  modules: ['@wxt-dev/module-vue'],

  vite: () => ({
    resolve: { alias: { 'devlog-ui': resolve(__dirname, 'packages/devlog-ui/src') } },
    define: { __APP_VERSION__: JSON.stringify(version) },
    ssr: { noExternal: ['@webext-core/storage', '@webext-core/messaging', '@webext-core/proxy-service', '@nuxt/ui', '@nuxt/icon'] },
    plugins: [vueJsx(), ui({...}), tailwindShadowDOM()],
  }),

  manifest: ({ browser }) => ({...}),
  webExt: { disabled: true },
})
```

### 1.1 目录与别名

- `srcDir: 'src'`：WXT 从 `src/entrypoints` 扫描入口
- `outDirTemplate`：产物目录名，例如 `chrome-mv3`
- `devlog-ui` 别名指向子模块源码，而不是 npm 包
- `__APP_VERSION__` 由 `package.json.version` 注入，供 UI 显示与更新比较

### 1.2 Nuxt UI 主题

`ui({...})` 中做了项目级定制：

| 配置 | 值 |
| --- | --- |
| `colorMode` | `false`（不维护暗黑模式） |
| `router` | `false` |
| `prose` | `false` |
| 主色 | `teal` |
| 中性色 | `gray` |
| warning / success / error | `orange` / `emerald` / `rose` |
| Modal overlay / content | `z-200` / `z-220` |
| Slideover content | `z-230` |
| FormField 默认方向 | `horizontal` |
| ChatMessage 右侧 | `flex-row-reverse justify-start` |

这些配置让 Nuxt UI 组件在 Shadow DOM 中保持统一的视觉与层级。

### 1.3 Tailwind 与 Shadow DOM

- `@import 'tailwindcss'` + `@import '@nuxt/ui'` 在 `src/assets/main.css`
- `vite-plugin-tailwind-shadowdom` 让 Tailwind 的样式选择器能正确作用于 Shadow DOM
- `main.css` 通过 `?inline` 被塞进 shadow root，而不是作为 content script CSS 注入页面

## 2. Manifest 解析

`manifest` 是一个函数，按浏览器返回不同配置。

### 2.1 公共字段

```ts
{
  default_locale: 'zh_CN',
  name: '__MSG_extName__',
  description: '__MSG_extDescription__',
  permissions: ['storage', 'notifications'],
  web_accessible_resources: [
    { resources: ['boss.js'], matches: ['*://zhipin.com/*', '*://*.zhipin.com/*'] },
  ],
  host_permissions: ['http://*/*', 'https://*/*'],
}
```

- **名称/描述**来自 `public/_locales/zh_CN/messages.json` 与 `en/messages.json`
  - 中文名：`boss-helper-直聘AI求职助手`
  - 英文名：`boss-helper`
- **permissions** 只申请了 `storage` 与 `notifications`
- **host_permissions** 是宽泛的 `http://*/*`、`https://*/*`，用于 AI 接口、高德、图片等跨域请求
- **web_accessible_resources** 只暴露 `boss.js`，且限制在 `zhipin.com`

### 2.2 浏览器差异

| 字段 | Chrome | Edge | Firefox |
| --- | --- | --- | --- |
| `key` | 固定公钥 | `undefined` | `undefined` |
| `browser_specific_settings.gecko.id` | — | — | `{1b66669d-c871-43f3-8c0c-d8a1c0566071}` |
| `strict_min_version` | — | — | `109.0` |
| manifest 版本 | MV3 | MV3 | MV3（脚本传 `--mv3`） |

Chrome 的 `key` 用于保持扩展 ID 稳定；Edge 交给商店分配；Firefox 用固定 Gecko ID。

### 2.3 入口

WXT 自动识别：

- `src/entrypoints/background.ts` → service worker
- `src/entrypoints/content.ts` → content script（`document_start`，`ISOLATED`）
- `src/entrypoints/boss/index.ts` → `boss.js`（unlisted script）
- `src/entrypoints/options/index.html` → options 页面（占位）

`boss.js` 是 unlisted script，不会自动出现在 manifest 的 `content_scripts` 中，只通过 `injectScript` 注入。

### 2.4 图标与语言

`public/icons/`：16、32、48、64、128、256、logo。

`public/_locales/`：

- `zh_CN/messages.json`
- `en/messages.json`

`default_locale` 是 `zh_CN`；`name`/`description` 使用 `__MSG_*__` 占位符。

## 3. 构建与打包命令

```bash
npm run build          # 依次执行 build:chrome / build:firefox / build:edge
npm run build:chrome   # node scripts/wxt-run.mjs build -b chrome
npm run build:firefox  # node scripts/wxt-run.mjs build -b firefox --mv3
npm run build:edge     # node scripts/wxt-run.mjs build -b edge

npm run zip            # 依次执行 zip:chrome / zip:firefox / zip:edge
npm run zip:chrome     # node scripts/wxt-run.mjs zip -b chrome
npm run zip:firefox    # node scripts/wxt-run.mjs zip -b firefox --mv3
npm run zip:edge       # node scripts/wxt-run.mjs zip -b edge
```

### 3.1 产物结构

```text
.output/
├─ chrome-mv3/
├─ edge-mv3/
├─ firefox-mv3/
├─ boss-helper-<version>-chrome.zip
├─ boss-helper-<version>-edge.zip
├─ boss-helper-<version>-firefox.zip
└─ boss-helper-<version>-sources.zip   # Firefox 源码包
```

实际文件名以 WXT 版本为准；`submit.sh` 与 CI 使用 `*-chrome.zip`、`*-edge.zip`、`*-firefox.zip`、`*-sources.zip` 通配。

### 3.2 `zip` 与 `build` 的关系

- `wxt build` 只生成目录
- `wxt zip` 会先构建再压缩
- Firefox 商店要求源码包，WXT 会生成 `sources.zip`
- CI 发布时把 `sources.zip` 排除在 GitHub Release 之外（但 `submit.sh` 会用它提交 Firefox）

## 4. CI：GitHub Actions

`.github/workflows/main.yml`：

```yaml
name: Build and Release
on:
  workflow_dispatch:
  push:
    tags: ['*']

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with: { submodules: recursive, token: ... }
      - uses: actions/setup-node@v4
        with: { node-version: 22, cache: npm }
      - run: npm ci
      - run: npm run zip
      - run: |
          mkdir release
          cp .output/*.zip release/
          rm -f release/*sources.zip
      - uses: actions/upload-artifact@v4
        with: { name: boss-helper, path: release }
  release:
    needs: build
    if: startsWith(github.ref, 'refs/tags/')
    steps:
      - uses: actions/download-artifact@v4
      - uses: softprops/action-gh-release@v2
        with:
          tag_name: latest
          name: Latest Build
          prerelease: true
          files: dist/*
```

要点：

- 触发条件：手动 `workflow_dispatch` 或 push 任意 tag
- **必须递归 checkout 子模块**，否则 `devlog-ui` 缺失
- 用 Node.js + npm 安装与打包
- 发布 job 只在 tag 时运行
- Release 固定写 `tag_name: latest`、`prerelease: true`，即每次 tag 都会更新同一个 “Latest Build” 预发布

### 4.1 版本号在哪里改

| 位置 | 用途 |
| --- | --- |
| `package.json` 的 `version` | WXT manifest 版本、UI 显示的 `VITE_VERSION` |
| `net-conf.json` 的 `version` | 远程“最新版本”，用于提示更新 |
| `net-conf.json` 的 `version_description` | 更新说明 |
| `README.md` 的徽章 | 商店版本，自动从商店读取，不需要手改 |

`App.vue` 的更新提示是字符串比较：

```ts
const isDot = computed(() => (helper.netConf.value?.version ?? '0') > VITE_VERSION)
```

字符串比较对 `0.5.10` vs `0.5.9` 这类版本会出错，发版时注意版本号位数保持一致。

### 4.2 发布前检查清单

- [ ] `package.json` 版本已更新
- [ ] `net-conf.json` 版本与说明已更新
- [ ] `npm run check` 通过
- [ ] `npm run lint` 通过
- [ ] `npm run fmt:check` 通过
- [ ] `npm run build` 三浏览器通过
- [ ] Chrome/Edge/Firefox 手动加载产物，确认 UI 与投递流程
- [ ] 确认没有提交 `node_modules`、`.output`、`.wxt`、密钥
- [ ] 打 tag 并 push，确认 Actions 成功
- [ ] 检查 GitHub Release 附件

## 5. 商店提交

`scripts/submit.sh`：

```bash
#!/bin/bash

proxychains -q npx wxt submit $1 \
--chrome-zip .output/*-chrome.zip \
--edge-zip .output/*-edge.zip \
--firefox-zip .output/*-firefox.zip \
--firefox-sources-zip .output/*-sources.zip
```

- `$1` 是 WXT submit 的子命令/参数（按 WXT 版本使用）
- `proxychains` 用于需要代理的网络环境
- 需要配置各商店的 API 凭据（Chrome/Edge/Firefox 的 client id/secret/token 等），具体环境变量名以 WXT 文档为准
- 提交前必须完成 `npm run zip`

## 6. 兼容性

### 6.1 浏览器支持

| 浏览器 | 最低版本 | 说明 |
| --- | --- | --- |
| Chrome | MV3 支持版本（约 88+） | 主要目标 |
| Edge | 基于 Chromium，支持 MV3 | 主要目标 |
| Firefox | **109+** | manifest 中 `strict_min_version: 109.0`，MV3 |

### 6.2 依赖的 Web 平台能力

| 能力 | 用途 | 备注 |
| --- | --- | --- |
| Shadow DOM | UI 隔离 | 现代浏览器均支持 |
| Custom Elements | `boss-helper-job` | 现代浏览器均支持 |
| `Object.defineProperty` / `__lookupSetter__` | 页面上属性劫持 | 依赖 Vue 2 的 `__vue__` |
| `AbortSignal.timeout` | 请求超时 | Chrome 103+/Firefox 100+，满足最低版本 |
| 正则后行断言 `(?<!...)` | 工作内容过滤 | Chrome 62+/Firefox 78+ |
| WebSocket + MQTT | 聊天 | 需要 `wss://ws6.zhipin.com` 可访问 |
| IndexedDB | 图片存储 | 扩展 origin 下 |
| `browser.storage.sync` | 模型/外观配置 | 有配额限制 |
| `injectScript` / `document.currentScript` | 主世界注入与通信 | `keepInDom: true` |

### 6.3 Firefox 特别注意

- 构建命令必须带 `--mv3`
- `browser_specific_settings.gecko.id` 固定，更新时不能变
- `cloneInto` 兼容代码在 `contentScriptShare.ts` 的 `ProvideContentAdapter` 中，但当前实际使用的是 JSON 字符串 + `CustomEvent` 的 `ProvideContentScriptAdapter`，不依赖 `cloneInto`
- Firefox 的 `browser.*` Promise 风格与 Chrome 的 `chrome.*` 回调风格由 WXT 抹平

### 6.4 站点兼容

扩展强依赖 Boss 直聘页面结构：

| 依赖 | 失效后果 |
| --- | --- |
| `#wrap.__vue__` | 找不到根实例，面板不挂载 |
| `.job-search-wrapper` / `.job-recommend-main` / `.page-jobs-main` | 找不到插入位置 |
| 页面 Vue 的 `jobList` / `pageVo` / `jobDetail` / `clickJobCardAction` / `pageChangeAction` | 列表/详情/翻页失效 |
| `window._PAGE`、`window.Cookie` | 无法取用户与 token |
| `wss://ws6.zhipin.com/chatws` + `wt` 协议 | 无法发消息 |
| `/wapi/zpgeek/friend/add.json` 等接口 | 无法投递/取详情 |

Boss 改版是这类项目最大的不可控因素。升级适配通常集中在 `src/entrypoints/boss/*` 与 `src/composables/useVue.ts`。

### 6.5 CSP 与注入

`boss.js` 通过 `<script src=...>` 注入，受页面 CSP 影响。若 Boss 收紧 `script-src`，可能出现：

- 脚本被 CSP 拦截
- 注入成功但 `document.currentScript` 为空
- `web_accessible_resources` 被拒绝

排查时看 Console 的 CSP 报错与 Network 中 `boss.js` 的加载状态。

## 7. 依赖与锁文件

- 锁文件：`package-lock.json`
- 包管理器：npm 10+（`packageManager: npm@10.9.9`）
- `.npmrc` 启用 `legacy-peer-deps=true`，因为 `openapi-typescript@7` 的 peer 仍是 TypeScript 5
- `zod`、`vite` 是显式依赖；它们同时是 AI SDK / Nuxt UI / WXT 的 peer，legacy 模式不会自动安装 peer
- `typescript` 固定在 6.x，`vue-tsc` 目前不能驱动 TypeScript 7 的原生包
- `package.json` 中 `overrides: { vite: "^8.0.16" }`，强制统一 Vite 版本
- 主要运行依赖：`@ai-sdk/openai`、`ai`、`mqtt`、`protobufjs`、`comctx`、`idb`、`partial-json`、`spark-md5`、`@nuxt/ui`、`vue`
- 主要开发依赖：`wxt`、`@wxt-dev/module-vue`、`vue-tsc`、`oxlint`、`oxfmt`、`sass`、`typescript`

升级依赖时的风险点：

- AI SDK 大版本升级会改变 `ToolLoopAgent`、`Output.json()`、`toUIMessageStream` 的 API
- Nuxt UI 大版本升级会影响组件 props 与主题配置
- WXT 大版本升级会影响 manifest 生成、`injectScript`、目录结构
- `protobufjs`/`mqtt` 升级可能影响聊天消息编码

## 8. 发布后的远程配置

`net-conf.json` 托管在 GitHub，扩展通过 jsDelivr 拉取：

```text
https://testingcf.jsdelivr.net/gh/hollyxun/boss-helper@main/net-conf.json
```

它可以在不发版的情况下：

- 提示新版本
- 推送公告（alert）
- 推送通知（notification）
- 更新商店链接与反馈地址

注意 jsDelivr 有缓存，修改后不一定立即生效。
