# 06 · AI 能力

boss-helper-plus 的 AI 能力由两部分组成：

1. **配置层**：多模型管理（`useModel`）与 Prompt 管理
2. **运行层**：`ChatModel` 把 Prompt + 岗位数据渲染成消息，调用 OpenAI 兼容接口，流式接收并写入 UI 状态

AI 目前用于四个场景：

- **AI 筛选**：让模型逐维度对比简历与岗位描述（技能 / 方向 / 经验 / 条件 / 学历 / 薪资），插件按固定权重算匹配度并定档，命中拦截档则过滤（投递前执行，结论与理由写入日志）
- **AI 招呼语**：让模型生成开场白，然后通过 Boss 聊天通道发送
- **AI 回复**：监听招聘方的消息，用模型生成一句回复并发送（0.0.2 新增）
- **简历推荐 / 摘要**：读简历给出岗位方向、搜索关键词和候选人摘要（摘要供 AI 筛选使用）

## 1. 模型配置的数据结构

### 1.1 `ModelConf`

```ts
interface ModelConf {
  key: string // 时间戳字符串，作为唯一 id
  name: string // 用户起的名字
  color?: string // UI 色块
  enable?: boolean // 渠道是否启用，未设置视为启用；仅启用的渠道进入 AI 功能下拉（useModel/index.ts 的 enabledModelData）
  data?: ModelConfData // 具体模型参数
}
```

`ModelConfData` 当前只有一种：

```ts
type OpenaiLLMConf = LLMConf<
  'openai',
  {
    avatar: string
    base_url: string
    api_key: string
    model: string
    responses?: boolean
    other: { timeout?: number }
    advanced: {
      json?: boolean
      stream?: boolean
      temperature?: number
      top_p?: number
      presence_penalty?: number
      frequency_penalty?: number
      tool_choice?: string
      tools?: Array<Record<string, any>>
      extra_headers?: Record<string, string>
      extra_body?: object
    }
  }
>
```

### 1.2 存储

- 键：`sync:conf-model`（`confModelKey = 'conf-model'`，无前缀 → 默认 sync）
- 结构：`ModelConf[]`
- 读取：`useModel().initModel()`，仅在 `App.vue` 的 `onMounted` 中调用
- 保存：`useModel().saveModel(true)`，管理页的启用开关、删除、复制、新建、导入每步都立即调用它落盘
- 改动即时持久化，不存在「点保存才写入」；编辑弹窗里的「取消」只是关闭弹窗、不改动表格数据，真正的「保存」在弹窗内（见 7.1）

### 1.3 默认与示例

`openai.ts` 中给出了 Base URL 与模型名的候选项（仅作为输入建议，不代表都可直接使用）：

- Base URL：`https://api.openai.com/v1`、`https://openrouter.ai/api/v1`、`https://api.deepseek.com`、`https://api.moonshot.cn/v1`、火山方舟、小米 MiMo 等
- 模型名：`gpt-4o`、`deepseek-chat`、`doubao-*`、`mimo-*`、`kimi-*`、`minimax-*` 等

模型名默认值是 `deepseek-chat`。

## 2. 从配置到 Provider

### 2.1 `createOpenAI` / `createModel`

```ts
const openai = createOpenAI({
  baseURL: conf.base_url,
  apiKey: conf.api_key,
  headers: conf.advanced.extra_headers,
})

return conf.responses
  ? openai.responses(conf.model) // Responses API
  : openai.chat(conf.model) // Chat Completions（默认）
```

- `responses: false`（默认）：走 `/chat/completions` 风格
- `responses: true`：走 OpenAI Responses API
- `advanced.extra_headers` 可以传自定义认证头
- `advanced.extra_body` 在表单里存在，但 `createOpenAI` 调用中没有直接使用；它可能由 AI SDK 的其它参数传入，当前代码未显式接线

> 注意：上面这段是 `openai.ts` 的 `createModel`，被“模型测试”（`LLMModelEdit.vue`）和“简历推荐”（`Tabs/Resume.vue:297`，走 `generateText`）使用；它不参与投递链路。投递中的 `ChatModel.createAgent` **没有**调用 `createModel`，而是固定使用 `provider.chat(conf.data?.model || 'gpt-4o')`。因此：
>
> - `responses: true` 对 AI 筛选/招呼语不生效，只影响测试
> - `advanced.json`、`advanced.stream` 也没有在 `createAgent` 中读取；是否 JSON 由 `createAgent(..., { json: true })` 决定

### 2.2 `LLMInfo`：配置即表单

`useModel/type.ts` 定义了一套“用对象描述表单”的类型：

```ts
type FormElm =
  | { type: 'input'; format?: 'url' | 'json' | 'avatar' }
  | { type: 'input'; format: 'number' }
  | { type: 'input'; format: 'menu' }
  | { type: 'slider' }
  | { type: 'switch' }
  | { type: 'select' }
```

`OpenaiLLMConf` 的每个字段都带：

- `value`：默认值
- `type` / `format`：控件类型
- `desc`：帮助文本
- `required`：是否必填
- `condition`：条件显示（例如 `tool_choice` 只在 `responses` 为真时显示）

`LLMForm.vue` / `LLMFormItem.vue` 递归渲染这些描述，因此新增一个模型字段通常只需要改 `openai.ts` 的 `info` 对象，不需要改模板。

### 2.3 新增 Provider 的成本

`useModel/index.ts`：

```ts
export const llms = [openai.info]
```

看起来支持多 Provider，但 `ChatModel.createAgent` 里写死了：

```ts
provider = createOpenAI({
  baseURL: conf.data?.base_url,
  apiKey: conf.data?.api_key,
})
```

所以当前实际上只有 OpenAI 兼容协议一种。要真正支持 Anthropic、Google 等，需要：

1. 定义新的 `LLMInfo` 与 `createModel`
2. 在 `llms` 中注册
3. 把 `ChatModel` 中的 provider 创建改为按 `conf.data.mode` 分发

## 3. Prompt 模型

### 3.1 数据结构

```ts
type Prompt = Array<{
  role: 'system' | 'user' | 'assistant'
  content: string
}>
```

`FormDataAi`：

```ts
interface FormDataAi {
  model?: string // ModelConf.key
  prompt: Prompt
  enable: boolean
}
```

`aiFiltering` 多两个布尔：`skipReject`（结论为「不建议投递」时拦下，默认 `true`）、`skipWatch`（结论为「谨慎投递」时拦下，默认 `false`）。0.0.4 及以前这里是 `score: number` 阈值，已废弃。

### 3.2 模板渲染

`src/utils/ai.ts`：

```ts
export function renderTemplate(template: string, data: any): string {
  return template.replace(/\{\{\s*([\w.]+)\s*\}\}/g, (match, path) => {
    const value = path.split('.').reduce((acc, key) => {
      if (acc && typeof acc === 'object') {
        const target = '__v_isRef' in acc ? acc.value : acc
        return target?.[key]
      }
      return undefined
    }, data)
    return value !== undefined && value !== null ? String(value) : ''
  })
}
```

- 只支持 `{{ a.b.c }}` 形式的路径，不支持表达式/函数/数组索引
- 遇到 Vue Ref 会自动取 `.value`
- 缺失值渲染为空字符串
- 因此 Prompt 中可以写：

```text
岗位名: {{ jobData.jobName }}
薪资: {{ jobData.salary }}
公司: {{ jobData.brand.name }}
地址: {{ jobData.address }}
```

注意路径必须以 `jobData` 开头（或其它真实存在的顶层字段），因为传入的是 `WorkflowData`：

```ts
{
  ;(jobData, rawData, state)
}
```

### 3.3 默认 Prompt

`defaultFormData` 里内置了四套默认 Prompt（AI 筛选、AI 招呼语、AI 回复、简历推荐）：

**AI 筛选**（`aiFiltering.prompt`）：

- system：扮演“求职评委”，要求逐维度对比简历与岗位描述，六个维度各给 `high` / `mid` / `low` 加一句话证据（`skill` 与 `direction` 必给，其余没信息时也填 `mid` 而不是省略字段），另外单独列硬性门槛，最后给一个整体结论：
  ```ts
  interface aiFilteringDimension {
    level: 'high' | 'mid' | 'low'
    reason: string
  }
  interface aiFiltering {
    verdict: 'recommend' | 'watch' | 'reject'
    hardFail: { rule: string; reason: string }[]
    match: {
      skill: aiFilteringDimension // 技能栈
      direction: aiFilteringDimension // 方向/岗位性质（转行、外包、纯销售…）
      experience: aiFilteringDimension // 年限
      conditions: aiFilteringDimension // 地点通勤、作息、是否上门/外勤/应酬/出差
      education: aiFilteringDimension // 学历
      salary: aiFilteringDimension // 薪资
    }
  }
  ```
- 提示词里同步写了权重和总分档位（技能 30 / 方向 22 / 经验 14 / 学历 10 / 条件 16 / 薪资 8；`>= 70` 建议投递、`>= 50` 谨慎投递），但明确要求模型**不要自己算分**——分数和档位由插件按同一张权重复核算出
- user：注入岗位名、薪资、学历、经验、城市与地址、福利、技能、标签、**公司名 / 行业 / 规模 / 融资阶段 / 招聘者姓名职位与是否猎头**、岗位描述。公司字段是 `direction`（外包、纯销售）和 `conditions`（通勤）两个维度的必需输入
- 简历为空时的兜底：六个 level 全填 `mid`、`hardFail` 留空 → 总分正好 50 → 落到「谨慎投递」，既不冒充匹配也不误杀

**AI 招呼语**（`aiGreeting.prompt`）：

- system：扮演“求职小能手”，要求输出不带书信格式的开场白
- user：注入岗位信息与描述

`aiReply` 已是一份完整的默认提示词（6 条规则：只输出要发送的内容本身、30 字以内、不编造经历、约面不敲定时间、不承诺具体薪资、不知道就坦言待确认），并在 `entrypoints/boss/autoReply.ts` 接线使用，只是默认 `enable: false`。`aiResume` 同样内置默认提示词（要求返回 `summary` 字段供 AI 筛选复用）。

### 3.4 Prompt 编辑器

`LLMPromptEdit.vue`：

- 选择模型
- 编辑 `system/user/assistant` 消息列表
- 增删消息、恢复默认
- “测试”：选择若干真实职位，批量调用模型并展示结果

## 4. `ChatModel` 运行机制

### 4.1 结构

```ts
class ChatModel {
  states: ShallowReactive<Map<string, VueChatState<Message>>> // 每个职位一个会话
  jobs: Ref<string[]> // 会话过的职位 key
  providers: Map<string, OpenAIProvider> // 按模型 key 缓存
  agents: Map<MessageRole, [ToolLoopAgent, ModelConf, FormDataAi]>
  generateId: Record<MessageRole, () => string>
}
```

`MessageRole`：

```ts
type MessageRole =
  'system' | 'user' | 'assistant' | 'boss' | 'jd' | 'filtering' | 'greetings' | 'reply'
```

其中真正用于 Agent 的是 `filtering`、`greetings` 和 `reply`——三者都通过 `createAgent` 建立 Agent（AI 回复用 `createAgent(aiReply, 'reply')`，见 `entrypoints/boss/autoReply.ts`）；`jd` 用于会话里展示职位描述。

### 4.2 创建 Agent

```ts
createAgent(model: FormDataAi, name: MessageRole, opt?: { json?: boolean }): boolean {
  const conf = models.modelData.value.find(m => m.key === model.model)
  if (!conf || !model.model) return false

  let provider = providers.get(model.model)
  if (!provider) {
    provider = createOpenAI({ baseURL: conf.data?.base_url, apiKey: conf.data?.api_key })
  }
  providers.set(model.model, provider)

  const agent = new ToolLoopAgent({
    model: provider.chat(conf.data?.model || 'gpt-4o'),
    output: opt?.json ? Output.json() : Output.text(),
    allowSystemInMessages: true,
  })
  agents.set(name, [agent, conf, model])
  return true
}
```

关键点：

- Agent 按**角色名**（`filtering`/`greetings`）存在 `agents` 里，每次 `createAgent` 覆盖
- Provider 按**模型 key** 缓存；如果用户改了同一个模型的 `base_url`/`api_key`，已缓存的 provider 不会更新。**修改模型配置后建议刷新页面再开始投递**
- `Output.json()` 会要求模型返回结构化 JSON（具体由 AI SDK 处理），`Output.text()` 返回纯文本
- 模型配置缺失时返回 `false`；调用方（`handles.ts`）会抛 `HelperConfigError`

### 4.3 一次对话 `chat()`

```ts
async chat(agentName, data, { disableMessages = false } = {}) {
  const [agent, modelConf, model] = agents.get(agentName)
  const timeout = modelConf.data?.other?.timeout ?? 60000

  // 1. 取 Prompt，渲染模板
  let messages = typeof model.prompt === 'string'
    ? [{ role: 'user', content: model.prompt }]
    : jsonClone(model.prompt)

  for (const msg of messages) {
    if (typeof msg.content === 'string') {
      msg.content = renderTemplate(msg.content, data)
    }
  }

  // 2. 初始化/复用该职位的会话状态
  //    首次会插入一条 jd 角色的职位描述消息

  // 3. 创建 assistant 消息，status = streaming
  // 4. agent.stream({ timeout, messages, ... })
  // 5. 逐 chunk 写入 text/reasoning part
  // 6. 出错时 state.status = 'error' 并抛出

  return stream
}
```

### 4.4 流式状态与日志

`VueChatState` 实现 AI SDK 的 `ChatState` 接口，用 Vue 的 `shallowRef` 保存消息，并提供：

- `pushMessage`
- `popMessage`
- `replaceMessage`
- `snapshot`

0.0.2 起独立的对话面板（`ChatBox.vue`）已移除，流式内容不再有专门 UI；每次调用结束后由 `addAiLog()` 写一条「AI 调用」日志，包含：

- 能力名称（AI 筛选 / AI 招呼语 / AI 回复 / AI 简历推荐）
- 渠道名、耗时
- 渲染后的完整提示词
- 模型返回的完整文本

日志页可以按「AI 调用」筛选、搜索回复内容、展开查看提示词与回复。

### 4.5 会话与职位绑定

- `states` 的 key 是 `jobData.key`（`boss::<encryptJobId>`）
- 每次 `chat` 会把职位 key 插到 `jobs` 数组头部（除非 `disableMessages`）
- 首次进入某职位会话时，会插入一条 `uiRole: 'jd'` 的系统消息，内容是职位名、薪资、公司、地址、学历、描述
- 该状态现在只用于同一次运行内的上下文复用，界面展示以日志为准

## 4.6 简历摘要与模板变量

`chat()` 渲染模板时会给每个 `{{ }}` 变量注入以下内容：

| 变量                             | 内容                                 |
| -------------------------------- | ------------------------------------ |
| `{{ resume }}`                   | 有候选人摘要时用摘要，否则用简历全文 |
| `{{ resumeSummary }}`            | 只给摘要（可能为空字符串）           |
| `{{ resumeFull }}`               | 永远是简历全文                       |

## 5. AI 筛选

### 5.1 调用链

```text
bossWorkflow -> tasks.aiFiltering
  -> createAgent(aiFiltering, 'filtering', { json: true })
  -> chatModel.chat('filtering', data)
  -> r.text
  -> parseFiltering(text)  // zod 核心必填校验 + 六维加权算匹配度
  -> verdict + skipReject/skipWatch ? skip : pass
```

### 5.2 `parseFiltering`：六维匹配度 + 本地权重复核

模型只负责逐维度判断，**分数和档位由插件算**：

```ts
const AI_FILTER_DIMENSIONS = [
  { key: 'skill', label: '技能', weight: 30 },
  { key: 'direction', label: '方向', weight: 22 },
  { key: 'experience', label: '经验', weight: 14 },
  { key: 'education', label: '学历', weight: 10 },
  { key: 'conditions', label: '条件', weight: 16 },
  { key: 'salary', label: '薪资', weight: 8 },
] as const // 合计 100，改这里要同步 conf/info.ts 默认提示词的权重段

const AI_FILTER_LEVEL_RATIO = { high: 1, mid: 0.5, low: 0 } // mid 计一半
const AI_FILTER_RECOMMEND_SCORE = 70
const AI_FILTER_WATCH_SCORE = 50

// 核心必填：verdict 是字符串、hardFail 是数组、match.skill 与 match.direction 必给；其余四维可省略
const aiFilteringSchema = z.object({
  verdict: z.string(),
  hardFail: z.array(z.unknown()),
  match: z.object({
    skill: aiFilterDimensionSchema, // { level: z.string(), reason: z.string().optional() }
    direction: aiFilterDimensionSchema,
    experience: aiFilterDimensionSchema.optional(), // 省略按 mid 计一半
    conditions: aiFilterDimensionSchema.optional(),
    education: aiFilterDimensionSchema.optional(),
    salary: aiFilterDimensionSchema.optional(),
  }),
})
```

判定顺序：

```ts
if (!raw || typeof raw !== 'object') issue = '返回的不是可解析的 JSON 对象'
else {
  const checked = aiFilteringSchema.safeParse(raw)
  if (!checked.success) issue = describeIssues(checked.error) // 最多列 4 条
  else {
    modelVerdict = VERDICT_ALIASES[checked.data.verdict...] ?? null // 只作对照
    for (const dimension of AI_FILTER_DIMENSIONS) {
      const item = checked.data.match[dimension.key]
      const level = item ? LEVEL_ALIASES[item.level...] : undefined // 认 high/mid/low，也认 高/中/低
      if (item && !level) {
        issue = `match.${key} 的 level 不在约定值里：...`
        break
      }
      const effective = level ?? 'mid' // 省略的非核心维度按 mid 计
      score += dimension.weight * AI_FILTER_LEVEL_RATIO[effective]
      dimensions.push({ ..., reason: level ? item.reason : '未评估', assessed: !!level })
    }
    if (!issue) verdict = scoreToVerdict(score)
  }
}

// 硬性门槛一票否决：在 if (issue) 之外单独判，顶层校验没过时依然生效
if (hardFail.length > 0) verdict = 'reject'
```

- **核心必填**（zod）：`verdict` 是字符串、`hardFail` 是数组、`match.skill` 与 `match.direction` 必给（两者合计 52 分，缺了就没法判断对口与否），缺任何一项判 `unknown`；其余四维是 `optional`，省略按 `mid` 计一半并标 `未评估`。第一版是六维全必填，实测有模型只给 `skill`/`education`/`salary`、把 `hardFail` 里「没有手机项目经验的不用投递」这种硬证据连同整份判断一起作废 —— 模型习惯把「没东西可说」的维度直接省字段，必填拦不住；按 mid 计则省略只能丢一半分，永远不会替岗位抬进 recommend。这也是本项目唯一用到 zod 的地方，`zod` 依赖先前只是挂着、没有任何 schema 校验
- **元素宽容**：`hardFail` 单条可以是字符串，也可以 `rule` / `reason` 只给一个（拼成「学历：要求本科」）；维度允许不给 `reason`；`level` 认英文枚举、也认 `高/中/低`、`匹配/一般/不匹配`
- **本地为准**：最终档位来自总分（`>= 70` recommend、`>= 50` watch、否则 reject），模型自报的 `verdict` 只在不一致时附一句「（模型自评：X，与本地核算不一致，以本地为准）」
- `unknown` 一定带 `issue`，写清是哪一个字段不对（`match.direction 应为 object，实际 缺失` / `match.skill 的 level 不在约定值里：ok` / 返回的根本不是 JSON），最多列 4 条，拼进 `message` 的「格式问题：」一行；**不当成及格放行**，且这时 `message` 里不写匹配度 —— `score` 是没算完的半截值，写成「0/100」会重演「同一个数值既表示档位又表示没判断」
- 没有换成 SDK 的 `Output.object({ schema })`：`base_url` 自定义的第三方网关很多不支持 structured output，而且这个 agent 的输出契约写在**用户可编辑的提示词**里，SDK 层硬校验会让自定义提示词从「优雅降级成 unknown」变成「请求直接失败」
- `message` 以 `AI 结论：` 开头是有意为之：`usePipelineCache.inferProcessorType` 靠消息里的「AI」字样把这条结果归到 `aiFiltering` 分组（7 天过期），否则会被算成 `basic`（3 天）
- `message` 会写入 `TaskResult.reason`，日志和卡片提示里能看到总分和逐维度得分与理由：

```text
AI 结论：不建议投递（匹配度 70/100）
硬伤：经验：要求 5 年，简历 2 年
技能 30/30 匹配：Vue/React 三年项目
方向 22/22 匹配：自研产品后端
经验 0/14 不匹配：要求 5 年只有 2 年
条件 8/16 一般：单双休未写明
学历 10/10 匹配：本科
薪资 0/8 不匹配：低于上份 20%
```

投递侧的判定（`src/composables/useApplying/handles.ts`）：

```ts
const { verdict, message } = parseFiltering(content)
const { skipReject, skipWatch } = ctx.helper.conf.formData.aiFiltering

if (verdict === 'unknown')
  return taskResult.skip(
    `${message}\n（提示词需要输出 verdict / hardFail / match.skill / match.direction）`,
  )
if (verdict === 'reject' && skipReject)
  return taskResult.skip(`${message}\n（命中「不建议投递」拦截）`)
if (verdict === 'watch' && skipWatch) return taskResult.skip(`${message}\n（命中「谨慎投递」拦截）`)
```

`recommend` 恒放行；两个开关默认「拦不建议投递、不拦谨慎投递」。

旧版（0.0.4 及以前）是 0-100 分制：`rating = clamp(0, 100, 60 + Σpositive − Σnegative)`，再和 `aiFiltering.score` 比较。因为每条固定 10 分，`rating` 只能落在 60±10n 的离散档位上，而默认阈值正好是 60，模型多挑一条毛病就翻面；且解析失败时 `rating` 恰好等于 60，会被当成「刚好及格」放行。现已废弃。

`parseGptJson` 使用 `partial-json`：

````ts
const match = json.match(/```json(.+?)```/s)
if (match) json = match[1]
return parse(json, ALL)
````

因此即使模型把 JSON 包在 Markdown 代码块里，或者只返回部分 JSON，也能尽量解析。

### 5.3 结构化输出

`createAgent(..., { json: true })` 使用 `Output.json()`，它只保证“返回的是 JSON”（等价于 `response_format: json_object`），**不保证字段符合 `aiFiltering` 接口**。字段级的约束由 `parseFiltering` 里的 zod schema 兜：核心必填（`verdict` 是字符串、`hardFail` 是数组、`match.skill` 与 `match.direction` 必给，缺一项就 `unknown` + 具体 `issue`），其余四维可省略并按 `mid` 计一半；元素宽容（`hardFail` 单条可以是字符串或只给 `rule`/`reason`，维度可以不给 `reason`，`level` 还认中文说法）。

没有改用 SDK 的 `Output.object({ schema })` 做结构化输出，两个原因：`base_url` 自定义的第三方 OpenAI 兼容网关很多不支持 structured output，硬上会直接请求失败；而且这个 agent 的输出契约写在**用户可编辑的提示词**里，SDK 层强约束会让自定义提示词从「降级成 unknown、日志告诉你哪不对」变成「整条任务报错」。`parseGptJson` 用 `partial-json` 宽松解析也是同一考虑：宁可解出半截 JSON 再交给 zod 判，也不要一断句就报错。

## 6. AI 招呼语

### 6.1 调用链

```text
bossWorkflow -> tasks.aiGreeting
  -> createAgent(aiGreeting, 'greetings')
  -> chatModel.chat('greetings', data)
  -> r.text
  -> helper.sendMessage(data, text)
```

- 没有变量渲染步骤（Prompt 内的 `{{ }}` 在 `chat()` 中统一渲染）
- 模型输出直接作为招呼语发送
- 发送失败会抛错，职位被标记为 `error`

### 6.2 和自定义招呼语的关系

AI 页 `src/components/Tabs/AI.vue` 中 `features` 里 `aiGreeting` 的 `help` 文案是：

> 开启后由 AI 生成招呼语，前面配置的招呼语不再发送。开场白很重要。

设计意图是 AI 优先。但两者在任务定义中共用 id `'打招呼'`：

```ts
tasks.customGreeting(...) // id: '打招呼', label: '自定义招呼语'
tasks.aiGreeting(...)     // id: '打招呼', label: 'AI招呼语'
```

管线按 id 去重，后定义覆盖先定义。实际效果：

- 只开 AI：正常
- 两个都开：AI 的 handler 和元数据生效，只发 AI
- 只开自定义：可能仍执行自定义的 handler，但任务元数据（label/state）来自 AI 定义，日志显示会不准确

这属于实现层面的缺陷，详见 [11-已知限制与风险.md](./11-已知限制与风险.md#3-代码层面的已知问题)。

### 6.3 AI 自动回复

0.0.2 新增，实现在 `src/entrypoints/boss/autoReply.ts`，不依赖投递管线：

```text
MQTT 'chat' 消息
  -> decode -> 只取文字消息
  -> 自己发的消息：记入上下文，结束
  -> securityId（优先）/ 招聘者 uid 找到 jobMaps 里的岗位
  -> 节流判断（同岗位 8s 间隔、最多 10 条）
  -> createAgent(aiReply, 'reply')
  -> chatModel.chat('reply', job, { extra: { reply, messages } })
  -> 清理引号 / 「回复：」前缀
  -> helper.sendMessage(job, text)
  -> addAiLog + addJobLog
```

- 上下文：每个岗位保留最近 12 条对话，渲染到 `{{ messages }}`
- 只覆盖投递过的岗位：`jobMaps` 现在只装投递过程中写入的岗位（页面钩子已删除），没投过的会话找不到岗位、直接跳过
- 提示词：`aiReply.prompt`，默认以求职者本人第一人称，要求 30 字内、不编造经历、不承诺薪资
- 日志：每次回复都会在「日志 → AI 调用」里留下提示词和回复，同时在「投递」分类里有一条 `AI 回复` 记录
- 未配置渠道时只记一条系统日志，不会反复重试

## 8. 错误处理与超时

### 8.1 超时

```ts
const timeout = modelConf.data?.other?.timeout ?? 60000
agent.stream({ timeout, messages, ... })
```

- 默认 60000（毫秒）
- `common.ts` 里的默认值是 `18000`，帮助文案写“18000s / 30分钟”
- 实际按毫秒传给 AI SDK，因此默认是 **18 秒**，不是 30 分钟
- 这是文案与实现的单位不一致，配置时不要按“秒”理解

### 8.2 错误

- `APICallError` 会被转换成 `请求错误 <status>: <message>`
- 其它错误直接使用 `err.message`
- 流式过程中出错：`state.status = 'error'`、`state.error = err`，`chat()` 最终抛出
- 任务层没有重试，抛错即该职位 `error`

### 8.3 常见错误

| 现象           | 原因                                     | 处理                                     |
| -------------- | ---------------------------------------- | ---------------------------------------- |
| `请求错误 401` | API Key 错误/过期                        | 检查模型配置                             |
| `请求错误 404` | Base URL 或模型名错误                    | 确认 `/v1` 与模型名                      |
| `请求错误 429` | 限流/额度不足                            | 降低频率、换 Key                         |
| CORS 错误      | 页面直接请求第三方 API，服务端未允许跨域 | 换支持 CORS 的中转，或改用支持跨域的服务 |
| 返回非 JSON    | 模型不支持 JSON 模式/输出被截断          | 换模型、降低 Prompt 复杂度、调高阈值容错 |
| 卡住不返回     | 超时单位误解/网络问题                    | 检查 `other.timeout`（毫秒）             |

`errorHandle()` 会把 CORS 类错误翻译成中文提示：

> 跨域或网络请求失败，xxx 可能不支持跨域请求，请尝试更换 API 地址

## 9. 安全与隐私

- API Key 保存在扩展存储（默认 `sync:`），不会上传到项目服务器
- Prompt 会把**职位描述、公司名、薪资、地址等**发送给用户配置的 AI 服务商
- 请求从页面主世界发出，受同源/CORS 限制；`request.ts` 虽然支持走 background 代理，但 AI 调用没有使用
- AI 调用记录会写进本地日志（`localStorage`，最近 200 条），其中包含完整提示词与回复；介意可随时清空日志
- 不建议在 Prompt 中放入身份证号、手机号等敏感个人信息
